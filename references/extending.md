# 扩展模块

两种扩展：加语言、加平台。都不需要改 `AGENTS.md` 的正文，只需要在分流表登记一行。

## 加一种语言：`lang-<语言>.md`

### 结构模板

```
# <语言> 规范

**加载时机**：<什么时候该读这个文件>

## 1. 版本与语言特性     ← 以构建文件为准，不写"最新"
## 2. 类型与空值
## 3. 并发
## 4. 异常与错误
## 5. 日志
## 6. 依赖与构建
## 7. 测试
## 8. 反例清单（见到就改）
```

章节可以按语言特点增减（比如 Go 不需要"空值与 Optional"，但需要"goroutine 泄漏"）。

### 内容原则

**只写这门语言特有的坑。** 通用纪律已经在 `AGENTS.md` 里了，抄一遍会让文件变长、重点被稀释。

判断标准：**这条规则换一门语言还成立吗？**

- 「提交前要跑测试」→ 任何语言都成立 → 不写，属于 AGENTS.md
- 「Java 的 `Long` 拆箱赋给 `long` 会 NPE」→ Java 特有 → 写
- 「Python 的可变默认参数在函数定义时只求值一次」→ Python 特有 → 写

**每条规则带触发条件。** 写不出"什么时候适用"的规则是废话，删掉。

**必须有反例清单。** 最后一节列"见到就改"的代码片段，比十条抽象规则管用：

```
## 8. 反例清单（见到就改）

// ✗ 用状态码判断业务成功
if (resp.getStatusCode() == 200) { ... }

// ✓ 用响应体里的业务字段
if (!res.ok()) throw new ApiException(res.reason());
```

### 规则强度的选择

| 情况 | 档位 |
| --- | --- |
| 违反会造成不可逆损失（数据丢失、密钥泄露、线上事故） | `【红线】` |
| 团队约定、可修正的错误 | `【默认】` |
| 风格偏好、性能优化建议 | `【建议】` |

一个文件里的红线控制在 3-5 条。超过 8 条说明分档失效了。

### 登记

在 `AGENTS.md` 第 3 节分流表加一行：

```markdown
| 新增/修改 <语言> 代码 | `lang-<语言>.md` |
```

如果有特征文件能让自动探测识别，第 2 节探测表也加一行：

```markdown
| `go.mod` | Go 项目；版本看 `go` 指令行 | `lang-go`（本仓库暂无，此处为示例） |
```

**不登记 = 永远不会被加载**。`scripts/check.sh` 第 3 项会检查这个，漏了 CI 直接红。

## 加一个平台：`release-<平台>.md`

平台指部署环境：k8s、Serverless、移动端、嵌入式等。

结构参考 `release-github.md` / `release-docker.md`：

```
## 0. 动手前          ← 先读什么、确认哪三件事
## 1. 触发与流程
## 2. 版本与产物
## 3. 配置与凭据
## 4. 部署
## 5. 验证            ← 唯一可信的几条判据
## 6. 回滚
## 7. 高频坑
```

三个必须有的章节：

1. **验证**：怎么证明"真的上线了"，不能只看流水线绿
2. **回滚**：出事时改哪个变量、跑哪条命令
3. **高频坑**：踩过的具体坑，带现象和原因

### 登记

```markdown
| 改 k8s manifest、调 Deployment | `release-k8s`（示例） |
```

同时在第 2 节探测表加识别条件：

```markdown
| `k8s/` / `helm/` / `kustomization.yaml` | 容器编排 | `release-k8s`（示例） |
```

## 反模式

| 反模式 | 问题 |
| --- | --- |
| 把语言的通用最佳实践抄一遍 | 文件变长、重点稀释，模型只记住开头 |
| 新增模块不登记分流表 | 永远不会被加载，等于没写 |
| 规则不带触发条件 | 不知道什么时候用，执行时全靠猜 |
| 全是【红线】 | 分档失效，等于没有优先级 |
| 只有正面规则没有反例 | 抽象规则难执行，具体反例好落地 |
| 把项目事实写进语言模块 | 换个项目就错，应该进 profile |

## 删规则比加规则重要

每次想加规则时，先问：**删掉哪条？**

规范的遵守率和长度成反比。一个 3000 字、20 条红线的文件，实际执行的是前 3 条。一个 800 字、5 条红线的文件，能全部执行。

规则该删的信号：

- 从来没被触发过（场景不存在）
- 和另一条重复（同一件事说了两遍）
- 写不出触发条件（"要注意代码质量"这类）
- 违反它没有实际后果（只是"更好看"）
